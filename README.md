# 桂养安心·旅居智管

面向广西旅居养老“智慧监管、规范发展”场景的可运行服务原型，包含老人端、养老机构端和主管部门监管端三类角色。项目以旅居老人智能建档和动态台账为主线，覆盖人群动态监测、服务质量监管、风险预警提示和应急联动调度。

## 本地演示登录

| 角色 | 账号 |
| --- | --- |
| 老人端 | `elder` |
| 机构端 | `center` |
| 监管端 | `admin` |

本地演示密码默认都是 `123456`（与启动窗口的提示一致），首次启动时写入**本机私有文件** `runtime/demo_credentials.json`；请不要把 `runtime/` 打包或公开。需要换成自己的密码时，在首次启动前设置 `GUIYANG_PASSWORD_ELDER`、`GUIYANG_PASSWORD_PROVIDER`、`GUIYANG_PASSWORD_REGULATOR` 环境变量。密码采用带盐 PBKDF2 校验，服务器只监听 `127.0.0.1`。`file://` 打开时是独立演示界面，没有服务端身份认证，不能录入真实个人信息。

## 本地完整服务

双击 `启动作品.bat`（详见下文"运行方式"）后访问窗口中打印的地址，默认 `http://127.0.0.1:4173/`。本地服务同时提供：

- SQLite业务数据库，首次启动自动创建 `runtime/guiyang_elders.db`。
- 老人档案、旅居记录、动向、服务、风险事件、授权和处置节点等规范化业务表。
- 机构报备在已登录页面之间通过 5 秒修订号轮询可见；呼救台账沿用 2 秒增量轮询。
- 不随业务状态覆盖而删除的操作审计，记录操作者、时间、动作和对象编号。
- DeepSeek安全代理；API密钥仅由本地服务读取，不进入前端代码或Git仓库。
- 急症安全分流优先于大模型；胸痛、呼吸困难、疑似卒中、骨折出血和自伤风险不会因模型回答而被降级。
- 离线模式仅是单机演示；呼救重试队列只保存在当前打开的浏览器内存中，关闭页面前断网记录可能丢失。
- 端口被占用时自动顺延到 4174-4182，并在窗口中打印实际地址。

本版场所风险为可解释的规则演示：机构报备、老人注意事项及监管动向列表均可看到评估。未踏勘地点显示“资料待核验”；巴马、崇左与东兴路线是明确标注的**合成案例**，不能当作真实路况或急救响应时间。涉老诈骗提示只针对“收益承诺、催促付款、索要验证码”等组合话术进行非定罪风险提醒。未接入真实场所核验数据、地图、公安反诈接口或外部调度接口。

求助语音输入使用浏览器 `SpeechRecognition`，浏览器可能通过自身语音服务联网处理；缺少权限或不支持时提示人工填写，不会注入固定的“识别文本”。本原型不用于采集真实敏感录音。

本地服务启用令牌与角色校验，`/api/state` 按业务对象合并写入，老人仅能读取本人相关档案，机构端仅能读取本机构老人及其记录；写入时按数据库原记录核对机构归属（16.0），超时升级由服务器后台值守推进、不依赖页面（16.0）；它仍是单机演示原型，多机构账号体系、专业权限审批、断网持久队列及外部短信/电话调度留待试点阶段。`api/chat.js` 是独立静态站点的可选演示代理，不提供本地服务的登录和数据持久化权限，不得接入真实个人信息。

源码回归：先用临时数据库启动 `python server.py`，再执行 `bash scripts/run_all_tests.sh`（两个窗口设置同一个 `GUIYANG_DB_PATH`，端到端脚本会重置这个临时库；单元测试始终使用各自的临时库，不受该变量影响）；其中 9 个浏览器端到端脚本需要 Python Playwright 和 Chromium。若服务或浏览器依赖缺失，脚本会明确失败。仅验证核心服务时执行 `python -m unittest discover -s scripts -p 'test_security_routes.py' -q`、`python scripts/test_review_fixes.py` 和 `node scripts/test_triage.mjs`。

本地密钥文件使用项目根目录下的 `deepseek.env.local`（Windows 隐藏扩展名时被存成 `deepseek.env.local.txt` 也能识别；打开 `http://127.0.0.1:4173/api/status`，`configured` 为 `true` 即表示已读到密钥）。页面和静态资源按“每次向服务确认新版本”返回，升级后刷新即可看到新界面，不需要清浏览器缓存。该文件已被 `.gitignore` 排除；制作源码包请用 `python scripts/package_release.py`，脚本按白名单打包并检查不含密钥、数据库和 `runtime/`（不要手工压缩整个文件夹）。新环境可复制 `deepseek.env.example` 为 `deepseek.env.local` 再填写。服务器也兼容读取桌面旧位置，便于已有配置迁移。正式云端部署时不要上传此文件，应在托管平台控制台中把 `DEEPSEEK_API_KEY` 设置为加密环境变量。

## 平台应急响应闭环（安心应答）

针对“喊救命只给一个120链接”的问题，参考网约车安全响应机制，新增贯穿三端的应急响应闭环：

1. **触发**：老人语音/文字出现呼救词（救命、快来人等）、AI急症分流命中高风险、一键呼救按钮（5秒防误触缓冲）或求助表单危险类目，均自动生成呼救工单，不再只弹拨号链接；120自呼渠道全程保留且优先展示。
2. **自动回拨确认**：演示环境仅模拟拨号→响铃→结果录入，没有真实电话回拨能力，值班人员可录入“接通确认危险 / 接通确认安全 / 未接通”，未接通自动重拨并升级通知。
3. **真人接单（SLA 30秒）**：机构值班队列实时倒计时，值班人员必须接单，接单时长自动留痕并计入机构响应时效。
4. **分级升级**：超30秒未接单在站内生成机构负责人与紧急联系人提醒（电话需人工联系）；超75秒生成监管端联动事件和最小照护摘要，外部联动由授权人员确认；监管端也可手动“立即联动调度”。
5. **闭环与留痕**：到场处置完成 / 确认安全办结 / 联动120·110三种闭环方式；老人误触可自助取消（留痕不追责）。触发、回拨、接单、升级、闭环全链路写入 `sos_sessions` 规范化表和审计日志，监管端展示平均接单时长、回拨接通率、升级联动与误触统计。

6. **值班排班**：接单人与值班联系人按当前时段自动从 `dutyRoster`（白班/晚班/夜班）取值，接单记录含班次。
7. **机构响应时效排行**：监管端按真实工单聚合各机构平均接单秒数、SLA 达标率与超时升级次数，机构无法自行填报，可直接用于服务质量评价。

演示时序：接单SLA 30秒、回拨响铃25秒判未接通（最多2次）、75秒升级监管联动。修改时要同时改 `watchdog.py` 的 `SOS_RULES`（服务器推进）和 `app.js` 顶部的 `SOS_CONFIG`（页面显示与离线演示）。

## 电脑端拨号提示

`tel:` 是手机拨号协议。在电脑浏览器上点击拨号按钮，Windows 会弹出"选择一个应用以打开此 tel 链接"的系统窗口——这是操作系统行为，不是程序故障。为了让演示与实际使用都干净，平台会先判断设备是否具备拨号能力：

- 手机/平板：保持原生 `tel:` 行为，点击直接进入拨号界面。
- 电脑：拦截跳转，改为弹出号码面板（大号数字、一键复制、说明文字），并提供"返回呼救进度"按钮回到原来的弹窗。
- 老人从平台入口拨打 120/110 时，会在呼救工单时间线留痕"本人从平台入口拨打120，平台响应同步进行"（同一工单同一号码只记一次，重复点击不会刷屏）。
- 演示数据中的脱敏号码（如 `0779-3882***`）不会生成无效的 `tel:` 链接，改用按钮打开号码面板并标注为演示数据。

## 实时联动与跨端同步

呼救工单是**只追加台账**，独立于整体状态快照：

- 新增 `GET /api/sos`（带 `?since=版本号` 的轻量轮询，无变化只回版本号）与 `POST /api/sos`（单工单增量写入），工单按 `updatedAtMs` 时间戳 last-write-wins，旧数据不会覆盖新数据。
- 机构端提交整体状态时**不再删除**自己未知的呼救工单（原实现会误删老人端刚创建的工单）；只有"恢复脱敏初始数据"会带 `reset` 标记显式清空。
- 前端同一浏览器多窗口用 BroadcastChannel 即时广播（实测 0.1 秒），跨设备用 2 秒轮询兜底（实测 1.8 秒）；断网期间的操作先留在本地重试队列，恢复联网后自动补传。
- 连接本地服务时（16.0 起），回拨推进和超时升级由服务器后台值守执行，所有窗口只渲染倒计时；只有离线演示（直接打开 `index.html`）才通过 localStorage 租约做 **leader 选举**，由一个窗口推进状态机。
- 机构端/监管端收到新呼救会播放提示音、弹出红色提醒并在后台标签页闪烁标题，可一键静音。

## 运行方式（两种）

**方式一：完整服务（含 SQLite 留痕）** —— 解压后双击 `启动作品.bat`，或在文件夹里执行 `python server.py`。端口 4173 被占用时会自动顺延到 4174-4182 并在窗口里打印实际地址。

**方式二：免安装演示（无需 Python，录视频够用）** —— 解压后双击 `index.html` 或 `备用启动_无需Python.bat`。三端登录、完整呼救闭环、倒计时与升级、跨窗口实时联动全部可用，数据存在浏览器本地，仅没有 SQLite 留痕。

### 打不开时的排查顺序

1. **是否解压？** 直接在压缩包里双击 bat，Windows 只释放这一个文件，`server.py` 不在旁边会立即失败。请先"全部解压缩"再双击。
2. **是否装了 Python 3？** 没装就用方式二，或到 python.org 安装时勾选 `Add python.exe to PATH`。
3. **窗口是否一闪而过？** 新版 bat 在所有失败路径都会 `pause` 并打印原因，请把提示内容截图。

## 核心业务链路

1. 老人通过视频场景中的语音或文字描述需求，系统生成简短行动卡。
2. 行动卡转化为带风险、责任单位、处置时限和证据摘要的求助事件。
3. 机构记录老人外出去向、预计返回、责任人及联系电话，并完成返回核验。
4. 监管端核验外出责任链；超时未归记录联动风险预警和跨部门处置。
5. 关键操作同步写入规范化业务表与审计日志，支持责任追溯和后续统计分析。

## 本次优化功能（2026-08-23）

- **可计算的返回时限**：机构外出报备使用日期时间字段 `expectedReturnAt`，系统每15秒检查进行中的动向；超过预计返回时间后自动标记“超时未归”，生成失联风险事件并关联原动向台账。
- **机构外位置继承**：AI对话生成事件时读取当前动向，事件继承老人机构外位置、外出责任人和关联动向编号，便于急救或公安先到最后已知地点。
- **跨区域授权校验**：跨市行程和离住返程提交前检查 `profile.consents.crossRegion`；未授权时阻止提交并引导先完成跨区域档案复用授权。
- **证据化事件详情**：风险事件记录关联动向、位置范围和判断依据，机构与监管端可在同一事件详情中查看责任链。

## 旅居守护智能体（AI视频助手 4.0）

老人在"AI视频助手"里说一句话（语音或文字），智能体不再只是"回答"，而是**查证 → 判断 → 准备动作**：

1. **安全红线先行**：胸痛、呼救等急症仍由确定性规则处理，直接进入呼救闭环，不交给大模型判断。
2. **大模型规划并调用工具**（DeepSeek 函数调用）：查个人档案、查当前动向、评估路线风险并给出更安全的替代路线、核查机构登记、检索相似案例。
3. **生成适老建议卡**：一句话结论 + 最多 3 条动作；电话只能从 120/110/12315/12345/机构值班电话中选，模型编的号码会被服务端替换。
4. **待确认动作**：外出报备草稿、求助工单、提醒家属。都需要老人点"确认"才执行；报备会以"待出发 / 待核验 / 待确认"进入机构端动态台账（服务端强制这些状态）。
5. **执行轨迹可审计**：界面逐步展示每个工具调用及结果（`agent.py`，接口 `POST /api/agent`）。

配置：在 `deepseek.env.local` 或环境变量中设置 `DEEPSEEK_API_KEY`（可选 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`，兼容任何 OpenAI 格式接口，如内网 vLLM/Ollama 部署的 Qwen）。未配置或调用失败时，自动改用同一组工具的本地规则规划，界面会标明"本地规则智能体"。演示场景数据（巴马山地路线、盘阳河平缓步道等）均为合成样本。回归测试：`python3 scripts/test_agent.py`。

## 类案雷达（监管端 5.0）

单个老人上报一件事，监管端往往只能逐件处理；同一个骗局换了几位老人、几个渠道出现时，逐件看很难发现。类案雷达把**不同老人分别上报的相似事件自动归并成"类案"**，让监管从"一件一件处理"转向"一类一类治理"：

1. **可解释的归并**（`case_radar.py`，不依赖大模型）：只看涉老诈骗风险、服务投诉、消费纠纷三类事件；按文本二元组相似度 + 共同关键线索（预付/定金、包吃包住、免费体检、索要验证码、转个人账户、收费高于公示等）+ 事件类别归并。至少 2 位**不同**老人上报才算类案，诈骗和收费投诉不会混在一起。
2. **研判报告**：配置了 DeepSeek 时，大模型只依据已归并的证据写研判（标题、共同话术、结论、最多 3 条建议），要求不编造、不直接认定违法；同一组证据只调用一次模型（缓存）。未配置或调用失败时使用模板研判，界面标明来源。
3. **一键处置**：
   - "向旅居老人推送防骗提醒"：老人首页出现主管部门的防骗提醒，**不含任何个人信息**，并可一键"问AI"让守护智能体核查自己遇到的情况；
   - "汇总证据移交反诈 / 督办机构整改"：生成一条关联全部个案的督办事件进入事件中心。类案记录汇总了多位老人的信息，服务端只向机构端和监管端返回，老人端看不到。
4. **权限**：`GET /api/radar` 仅机构端、监管端可访问；推送提醒只有监管端能写，服务端只保留规定字段并限制长度。

演示数据新增 4 条合成事件（巴马"长寿养生基地"定金、长寿村康养旅居团预付款、以房养老高回报投资、理疗收费高于公示），数据版本升为 5，旧数据库启动时自动升级。回归测试：`python3 scripts/test_case_radar.py`。

### 6.0：实时发现 + 关系图（决赛现场演示）

- **实时发现**：监管端台账一有新上报（每 5 秒检查一次），就自动重新研判。某个类案加入了新老人、或出现新类案时，右上角弹出雷达提示「第 N 位老人报告了同一话术」，写明命中哪些线索、并入哪个类案。类案编号以最早的个案为准，有人加入也不变，已做的处置继续有效。
- **关系图**：每个类案画出「上报老人 → 命中的话术线索 → 指向的名义」三列连线，连线依次画出；新加入的老人用红色标出，点老人可查看原始上报。
- **页面实时指示**：页头的雷达扫描标识显示「实时监测中」和最近一次研判时间。

### 7.0：预警效果闭环

- **AI 助手认出已发布的提醒**：老人遇到的情况和主管部门推送过的防骗提醒是同一种说法时（至少命中该类案 2 条共同线索），智能体会直接说「这和主管部门刚发的防骗提醒是同一种说法」，执行过程里也会写明命中了哪条提醒。生成的工单会记下命中的是哪条提醒。
- **效果数字**：类案卡片底部显示「已提醒 N 位旅居老人 · 预警后主动求证 k 起」。「预警后主动求证」统计的是老人收到提醒后、先问 AI 再上报的次数，系统不核实付款结果，因此不写「未付款」「已拦截」。关系图里这类老人标绿。统计指标卡新增「预警后主动求证」。
- **监管总览**：顶部新增类案雷达摘要（发现几类、涉及几位老人、几类待处置、主动求证几起），点一下直接进入雷达。
- **人数与件数分开**：同一位老人多次上报时，卡片显示「4 位老人 · 5 件」，高风险判定按不同老人的人数计算。

**决赛演示脚本（约 30 秒，两台电脑或同一屏幕左右两个浏览器窗口）**

## 评阅整改：越权写入、指标口径、真实时限、后台值守（16.0）

起因：模拟评阅报告指出 5 个必须先修的问题（P0）和 10 处页面问题。这一轮不加新场景，只修“数据可不可信、流程靠不靠谱”。

**5 个 P0 问题**

1. **机构不能改别家机构的记录**
   - 登录时把账号所属机构记进会话；每次写入都按数据库里的原记录核对归属，而不是相信页面发来的字段。
   - 机构 A 改机构 B 的档案、服务记录、外出报备、事件，一律返回 403，数据库不变；想通过改 `institution` 或 `residentId` 把记录“搬”到本机构，同样被拒绝。
   - 新建档案自动归属登录机构；呼救工单、路线评估、设备告警、报平安代报也按机构限定。
2. **接单达标率不再“只算接了单的”**
   - 分母包含超过 30 秒仍无人接单的工单：整体响应达标率 = 按时接单 ÷（按时 + 超时后才接单 + 超时未接单）。
   - 30 秒内本人取消（误触）、仍在 30 秒内等待的工单不计入；“已接单中的按时率”单独列出。
   - 页面上的达标率都带分母，例如“1/3（33%）”。评阅报告里的例子（1 张 10 秒接单、2 张超时没人接）现在显示 1/3，而不是 100%。
3. **事件时限按真实时间算**
   - 创建、截止、办结时间都由服务器写入（毫秒，同时存进 `risk_events` 的 `created_at_ms`、`due_at_ms`、`closed_at_ms`）。
   - “剩余 1小时5分 / 已超时 2小时 / 按时办结 / 超时办结（超40分钟）”都按这些时间实时算；更新备注、转派不会重置截止时间，刷新后结果一致。
   - 办结必须写处置说明并选回访结果，老人不认可不能办结；已办结改回处理中算“重新打开”，要写原因并留痕；时间线只能追加，不能删改。
4. **超时升级交给服务器后台值守（`watchdog.py`）**
   - 服务器每秒扫描一次：模拟回拨推进、30 秒没人接单通知负责人和家属、75 秒升级监管联动（生成联动事件）、外出过了预计返回时间标“超时未归”并生成失联事件、报平安超时转机构负责人。
   - 关掉所有页面也照常推进，审计里记为“后台值守”；服务重启后的第一次扫描会补上停机期间错过的推进；每次扫描在一个数据库写事务里完成，推进过的不会重复。
   - 页面只负责显示。直接双击 `index.html` 的离线演示没有服务器，仍由页面计时。
   - 读取 `/api/state` 不再顺带改数据；呼救工单按字段合并：升级只升不降、时间线只追加，页面上的旧副本不会把服务器已做的升级覆盖掉。
   - 服务器拒绝的修改（越权、缺少处置说明、工单已被他人接单等）不会留在页面上：提示“这次修改没有保存”，并恢复为服务器记录；不再误报“数据库暂时离线”，也不会反复补传。
5. **交付包不再带私有文件**
   - 新增 `scripts/package_release.py`：按白名单打包，排除 `deepseek.env.local`、`runtime/`（数据库、备份、账号密码、模型缓存）和 `__pycache__`；打包后逐个检查文件名和内容，发现疑似密钥就报错退出。
   - 附空白模板 `deepseek.env.example` 和 `.gitignore`（排除密钥、`runtime/`、数据库和缓存）。用法：`python scripts/package_release.py`，在项目上一级生成 `桂养安心_源码16.0.zip`。
   - 14.0 的压缩包里带过密钥文件；如果那个包发出去过，请到 DeepSeek 控制台换发新密钥、停用旧的。

## 小桂的反应更合乎常理：家人要钱先核实、28 个生活情景实测（15.3）

起因：老人说“我儿子最近说住院了，要我转他1000”，小桂直接让她“马上打110报警、让银行止付冻结”，还生成了报案工单。钱还没转，这件事也可能是真的，这样处理反应过度。

**家人要钱分成四种情况**（`agent.family_money`）
| 老人的话 | 判断 | 小桂怎么做 |
| --- | --- | --- |
| 儿子说住院了要我转1000 / 女儿想借两千周转 | 先核实 | 先别转；打这位家人**平常用的号码**亲口问；说清什么情况才是骗子。只生成“请儿子回个电话”的提醒（要老人确认），**不报警、不开工单**；风险为“需关注”。 |
| 有人说是我儿子出车祸让我马上转账 / 换了新号、让保密、猜猜我是谁、在派出所要保释金 | 有冒充迹象 | 按诈骗处理：110、工单、提醒家属。 |
| 已经给“儿子”转了5000 | 已经转了 | 第一条就是报警和银行止付。 |
| 孙子结婚我想给他转两万 | 老人自己给钱 | 不是诈骗，只提醒转账前打电话核对账号。 |

- 界面：“先核实”时，联系电话一格显示档案里登记的家人，比如“儿子李明辉 · 138****7281”，按钮是“打给儿子李明辉核实”。
- 老人说的是女儿，而档案登记的是儿子时，会说“打女儿平常用的号码……也可以请儿子李明辉帮您问问”。
- 所有在住老人都补上了紧急联系人（数据版本 10），机构端的“动态档案”显示紧急联系人和居住方式。
- 数据版本升级时，旧的演示库在重置前会自动备份到 `runtime/backups/`（原来重置时不留备份）。

**建议卡更干净**
- “地点 / 路线”“费用”两格只在与这件事有关时显示，模型不再硬凑“投诉不用花钱”这类话。
- 在对话里点拨号，不再弹出拨号窗盖掉整个对话：手机上直接拨号，电脑上在卡片里展开号码。

**28 个生活情景**（DeepSeek 测试新增“情景”组，Q1～Q28）
- 覆盖七类：家人要钱、日常花钱（买水果、门票、饭卡充值、药店买药）、各种骗局（点链接解冻、代办补贴收手续费、扫码领红包、墓地升值）、身体（头晕、忘吃药、膝盖酸、摔倒）、出行（夜里去海边、回老家、台风天买菜）、服务（热水器坏、护工不耐烦、换房间）、边界（打听别人电话、想老伴）。
- 每条都写明“合理反应”的标准，比如：钱没转，第一句不能让老人马上报警；日常花钱不能判为诈骗；小毛病不给 120。
- 实测发现并修复了三个问题：
  - “食堂饭卡没钱了怎么充值”被判为诈骗，还给了 110。现在“充值”“办卡”只有带返利、送、打折这类话术才算可疑。
  - “我摔了一跤，现在站不起来”没有进急症红线。摔倒规则原来要求两处词挨得很近，现在放宽了，服务端和本地兜底两处一起改。
  - 老人去超市这类小外出，模型常漏掉外出登记。提示词写明“只要离开机构就生成登记草稿”。

**其他**
- 老人首页“要办的事”和“我的求助”：看办理进度先找机构值班；只有高风险健康问题给 120，人身安全、失联给 110（原来普通的血压提醒也挂着 120 按钮）。
- 监管总览：“机构质量”表把**机构填报分**和**台账核算分**并列显示，差 10 分以上标黄。“今天要处理的事”里多了一条“1 家机构填报分明显高于台账核算”，并附扣分原因。原来首页只显示填报的 94.2 分，态势研判页却是 74.0 分，容易被追问。
- 常问问题加了第 4 条“儿子说住院了，要我转他1000”，演示指引第 3 步也加上了这句，用来展示 AI 分得清“家人真要钱”和“有人冒充”。
- AI 主动预警的提示词写明只能引用这位老人自己的编号：连跑 6 次，没有再出现引用别人编号的情况。
- **呼救进行中也保留“直接拨打120”**：原来老人按了一键呼救后，首页整块换成响应横幅，120 按钮不见了。现在横幅下方始终保留，符合“120 自拨渠道始终保留”的原则。
- **监管参谋查老人不再少算人**：查询结果只列前 10 位，第 11 位蒙秀英（防城港）被截掉，模型就说“11 位老人都在北海”。现在另附按机构、按居住方式的人数统计，也返回入住日期；回答里偶尔带出的英文工具名会换成中文。

## 逐项实测与贴近实际工作的修补（15.2）

做法：每个功能先用真实 DeepSeek，按监管员、机构和老人平时真会说的话去问；发现问题就修，修完再测，再做下一项。原则不变：不加新场景，关键动作仍要人确认。

**AI 监管参谋**
- **查老人**：新增“查询老人档案”，可按姓名、独居、居家或社区、机构、风险、客源地查询。
  - 结果不含电话和证件号，居家老人的住址只到小区。
  - 原来问“独居老人住哪”，参谋答不上来，还拿设备编号当证据。
- **按编号查记录**：问题里写了编号（EV、MV、GX 等），会先把记录查出来再回答。
  - 原来会把真实存在的事件说成“台账中未显示”。
- **只读保护**：监管员说“把某件事标记为已办结”“转派给公安”，参谋先说明“只能查询，不能直接修改台账”，再告诉他这件事现在的状态、该由谁在哪里办。
- **起草督办通知**：说“起草一份给某机构的督办通知”，会生成通知草稿，写明标题、致送单位、事由（带事件编号）、逐条督办要求和时限、回复方式和落款。
  - 可一键复制，下载的督办简报里也附上草稿。
  - 草稿里只保留核对过的编号，不写“违法”“处罚”等定性用语。
- 证据链接：点老人档案号跳到“人群监测”；设备、天气类编号换成对应图标。

**AI 主动预警**
- 有未办结的涉诈线索、或涉及涉诈类案的老人，至少列为“今天留意”，模型不能降到“常规”（骗子常会再联系）。
  - 原来黄德明、周桂英都有巴马养生基地的预付款线索，却被列为常规。
- 没有模型建议时，按信号给对口的动作：超时未归先“立即组织寻找并联系家属”，涉诈给“社工当面提醒先别交钱”，手环电量低给“提醒充电”。一句话结论改成短句，不再把信号原文拼在一起。
- 修复标签“外出外出中”。

**老人端小桂**
- **电话按事情选**：
  - 服务态度、饭菜这类投诉，先给机构值班电话（原来一律给 12315）；12315 只用于收费、退款等消费纠纷。追问时结合前文判断，比如先说“多收了钱”，再问“他们不承认怎么办”，仍给 12315。
  - 一般身体不适给机构值班电话，只有判为高风险才给 120（急症仍由安全红线先处理）。
- **给家人转钱不当诈骗**：老人主动说给孙子随礼、给家里生活费，没提到催促、换号、陌生账号时，只提醒转账前打家人常用电话核对，不开工单、不提醒家属。“孙子发微信说换了新号要转钱”仍按诈骗处理。
- **会销识别**：“免费领鸡蛋、送礼品”的讲座按涉老诈骗处理。
- **不说没依据的话**：“健康讲座”“理疗馆”“社保局”“旅行社”“楼下卖保健品的”这类泛称，以及括号里的说明，不再当成机构名去核查。所以不会再说“这家讲座在登记名单里没查到”。
- **模型自己开工单**：提示词写明“工单和提醒家属都只是草稿，要老人点确认才发出，符合条件就直接调用，不要先问老人”。
  - 三类诈骗说法各测 6 次，需要规则补工单的次数从约 6/18 降到 1/18。

**每日打卡**
- 打卡页的“补充说明”原来没有保存，现在会存下来。同一天重复提交只留最新一条（原来服务端会存两条）。
- 页面原来写着“连续异常会通知机构”，实际没有通知。现在规则是：
  - 今天有较重的异常（睡眠较差、食欲较差、心情低落、行动困难），或连续两次打卡都有异常，由**服务端**生成关怀提醒。
  - 提醒只给本机构，出现在“今天要处理的事”和通知中心里，并附上老人自己写的说明。
  - 老人看到的是“已告诉机构，今天护理员会来当面看看您”。
  - AI 主动预警会把这四项和“连续两次异常”一起纳入判断。
- **通知中心**：原来只列事件、动向和呼救，已保存的提醒一条都不显示。现在会按身份显示：老人只看自己的，打卡关怀提醒不给监管端。

**老人端“我的求助”**
- 由员工用的数据表格改成一件事一张卡片：
  - 状态用大白话写，比如“已收到，等工作人员核实”“正在处理”“已转给市场监管部门处理”；
  - 卡片上写明最新进展、谁在负责、还剩多久；
  - 每张卡片有“查看详情”“打电话问问”两个按钮；
  - 已办结的单独放在下面。

**验证**
- 离线测试新增 13 项，全部通过。
- 浏览器端到端：6 组呼救 82/82、对话 16/16、页面巡检 270/270。
- DeepSeek 新增监管参谋用例 A11～A13（独居、要求修改台账、起草通知）。
- **DeepSeek 实测（126 次调用）**：演示用句 12/12、自由说法 48/48、闲聊 9/9、多轮 12/12、安全红线 6/6、监管参谋 39/39、主动预警 3/3。
  - 靠规则补全的次数：演示用句 2 次、自由说法 13 次、多轮 3 次（15.1 时分别为 4、15、4）。
  - 报告见 `测试结果/DeepSeek测试_20260927_1423.md`。

## 小桂对话改为聊天式、浏览器自动测试补齐（15.1）

起因：老人说一句“你好”，也会弹出一整张“现在先做 / 地点 / 费用 / 电话”的建议卡；朗读按钮在卡片最底下，要往下翻才能点到。

**对话框**
- **像聊天软件一样**：回复和建议卡都在对话里，建议卡紧跟在小桂那句话后面；输入框始终固定在底部，不用上下翻找。
  - 回复出来后，自动把这句话的开头停在对话区顶部，老人从第一句读起。
  - 建议卡不再重复第一句话。“判断依据”默认收起，改叫“为什么这样建议”。
  - 常问问题放在对话里，发出第一句话后收起。
  - 等回复时显示“小桂正在帮您查”的动画。
- **打招呼、道谢不出卡**：“你好”“谢谢”“好的”“再见”“你是谁”等，由页面直接回一句，不调用模型，也不查证。
  - 闲聊（如“今天天气真好”）和倾诉心情（如“我有点想家”）交给大模型，只回一两句贴心话。
  - 实测回复约 2 秒，不调用任何工具。
  - 规则兜底不变：话里带“交钱、多收费、想去哪”等字眼，仍按诈骗、投诉、出行处理并出建议卡；急症仍先走安全红线。
- **朗读按钮跟着每句话**：小桂说的每句话下面都有“听一遍”，正在念的那句显示“停止”。有建议卡的那句会连同“现在先做”和电话一起念。
- 顶栏可以直接开关“自动朗读”；“开启画面”改成顶栏小按钮，开启后在对话区右上角显示小窗。

**智能体（agent.py / server.py）**
- 新增 `mode` 字段，取值 `chat`（只回一句话）或 `card`（出建议卡）。
  - 意图新增 `chat`；闲聊和倾诉心情没有生成待确认动作、也不是高风险时，按 `chat` 返回。
  - 本地规则“没听明白”时也只回一句话。
- 打招呼、道谢在服务端同样直接回复。修复了一个问题：没配置大模型时，老人在诈骗问题后说“谢谢”，会和上一句拼在一起再生成一次工单。
- 老人没说出机构名时，模型说“查不到登记信息”这类没有依据的话也会被删掉（原来只拦“登记名单里没查到”）。
- 规则补全只看页面上实际显示的第一句话和前 3 条建议。原来模型把“带证件”写在第 4 条时，规则以为已经提过，结果这条被截掉，老人看不到。
- 低价出境团被判为诈骗时，也会补上“低价团常带进店强制购物”的提醒（原来只在按出行处理时补）。
- **DeepSeek 实测（117 次调用）**：演示用句 12/12、自由说法 48/48、闲聊 9/9、多轮 12/12、安全红线 6/6、监管参谋 30/30、主动预警 3/3。报告见 `测试结果/DeepSeek测试_20260927_1332.md`。

**浏览器自动测试**
- 安装了 Playwright，原有 6 个呼救端到端脚本全部通过（82/82）。
  - 其中两个脚本还在等 15.0 改版前的首页类名 `.quick-action`，改成等 `.sos-band`。
- 新增 `scripts/e2e_ai_dialog.py`（16 项）：检查闲聊不出卡、朗读按钮位置、建议卡位置、不重复第一句、自动朗读开关等。

## 对话证据链、适老朗读与天气报平安（14.0）

这一轮延续现有三端界面，重点让风险判断**有依据、老人听得清、预警后有人跟进**。演示数据版本升为 9；新版本首次启动会按种子数据重建旧版演示库，使用前请另存自己添加过的演示记录。

**安全防护设备接入（机构端「安全设备」）**

## AI 主动预警（12.0）

前面的 AI 功能都要等老人开口、监管员提问才启动。12.0 让 AI **主动**去看台账：每天把快筛、服务记录、未办结事件、外出动向、类案、档案更新时间扫一遍，找出**今天谁最需要关注**，写清谁在什么时限内做什么。机构端和监管端的侧栏都新增了「AI 主动预警」，首页顶部有一条红色提示。

- **规则先列信号**（`care.py`）：每位老人一份信号清单，每条带证据编号（事件 EV-、动向 MV-、服务记录 SV-、类案 CL-、档案编号），按权重算出规则优先级。「超时未归」这类信号直接定为高危。
- **DeepSeek 把信号连起来看**：单条信号看不出的风险，要几条合起来才看得出，例如：
  - 陈美华：有涉诈线索（推销巴马养生基地投资），明天又要独自去南宁 → 可能被约去当面交钱；
  - 王建国：头晕、血压偏高，同时被冒充孙子要学费 → 情绪激动可能让血压更不稳。

  AI 给出优先级、一句话结论、「AI 看到的关联」和最多 2 条建议（岗位 + 做什么 + 时限）。AI 调整了规则优先级时，卡片上标「AI 上调 / AI 下调」。
- **代码兜底**：
  - AI 引用的编号必须出现在信号清单里，否则删除，卡片上注明删了几个；
  - AI 不能把规则判定的高危（如超时未归）降级；
  - AI 没提到的老人照常显示规则结果；模型不可用时整页退回规则排序；
  - 不做医学诊断，只说「需要关注」「建议复测/就医评估」。
- **先快后准**：页面先拿到规则结果（几乎即时），再等 DeepSeek 研判（约 10～30 秒）后自动替换。结果按信号内容缓存，台账没变不重复调用。
- **形成闭环**：机构端在卡片上点「生成随访任务」，会把 AI 的第一条建议写进动态台账（类型「AI预警随访」、状态「待执行」），并留操作审计。随访任务本身不再算作风险信号。
- **监管参谋联动**：参谋新增只读工具「查询主动预警」，可以问「今天哪些老人最需要重点关注？」。这个工具只读取已有结果，不额外调用模型。
- **权限**：`GET /api/care` 仅机构端和监管端可用；`?mode=rules` 只返回规则结果。
- **测试**：
  - 单元测试：`python3 scripts/test_care.py`，覆盖信号、不降级、编号核对、缓存和模型失败回退；
  - 真实 DeepSeek 测试：`DeepSeek测试.bat` 新增「主动预警」组（每轮清空缓存重新研判）。硬性要求：孙和平、王建国判高，赵秀兰不判高，不编造编号，高危建议有执行人和时限。加分项：看出陈美华「涉诈 + 跨市出行」的组合风险。

## 多轮追问（11.0）

老人端 AI 能接着前面的对话往下聊。例如先问「有个养生基地让我今天交一万块定金」，再问「那我要是已经交了怎么办？」，AI 会明白「交了」指的是那笔定金，回答「马上打 110、联系银行止付」。

- 页面会把最近 6 轮对话带给 AI。老人的原话按原样带上；AI 之前的回答只带摘要和建议，避免越积越长。前端传来的其他角色一律丢弃，防止有人伪造系统指令。
- 执行过程里会多出一步「结合前面的对话」；追问时照样调用工具查证，安全红线也照常先判断。
- 未配置密钥时（本地规则模式），如果追问里看不出具体是什么事，就把上一句一起拿来判断。
- 测试：`DeepSeek测试.bat` 新增「多轮追问」组，共 4 段对话。检查 AI 对追问的回答有没有接上前文，例如定金已交的情况要提到报警或止付。

## 类案雷达 · AI 线索抽取（10.0）

原来的归并只靠手写的线索词，比如定金、养生基地、今天交。换一种骗局，这些词对不上，就归不到一起。10.0 让 DeepSeek 读每一条上报，抽取**手法、涉及名义、具体话术**，手法相同的上报自动归成一类。**AI 会给没见过的新手法起新的类型名，形成新类案。**

- **一次抽取，结果缓存**：每条事件按「编号 + 文本指纹」只抽取一次，多条合并成一次调用；结果存在 `runtime/radar_ai_cache.json`（不进仓库）。
- **类型名统一**：已有的类型名会一起交给模型，同一种手法必须沿用原名称，确实是新手法才起新名。
- **防止乱归并**：「其他」「未知」这类泛称不参与归并；AI 给出的涉及名义必须在原文里出现过。
- **规则和 AI 并用**：规则归并照常进行，AI 在此基础上补充。类案卡片上会标注发现方式：
  - 「由 AI 发现」：规则完全没有找到这一类；
  - 「AI 补充归并」：规则已找到这一类，AI 又归入了规则漏掉的上报。

  AI 抽取的话术在线索和关系图里用蓝色虚线标出；AI 发现的类案按手法命名，例如「疑似“冒充亲属借钱”手法的涉老诈骗类案」。
- **演示数据**：新增 2 条「冒充亲属借钱」上报（数据版本升为 6），分别是王建国遇到的「孙子」换号要学费、孙和平接到的「儿子」出事要钱，两条说法完全不同。
  - 只用规则时，这 2 条归不到一起；
  - 开启 AI 后，形成第 3 个类案，并标注「由 AI 发现」；
  - 老人端现场说「我儿子发微信说换了新号，让我转两万」并确认提交后，监管端会弹出「类案扩大 · 第 3 位老人」。
- **只读场景**：监管参谋和老人端智能体只读取缓存结果，不会额外产生调用费用。
- **评测**：`DeepSeek测试.bat` 新增「AI 线索抽取」一节：
  - 检查演示数据中能否找出规则漏掉的「冒充亲属」类案；
  - 另用 7 条未参与调优的样本（保健品会销 3 条、冒充公检法 2 条，另有干扰项），计算两两配对的准确率和召回率。

## AI 监管参谋（监管端 9.0）

监管员在「AI 监管参谋」页用一句话提问，例如「这周有哪些事要督办？」「有没有老人外出超时没回来？」「北海银龄康养中心最近投诉多吗？」。DeepSeek 会自己决定查哪些台账，然后给出研判结论、带证据编号的发现和督办建议，还能一键下载督办简报（文本格式，需人工审核后印发）。

- **只读工具**（`advisor.py`）：监管总览、事件台账、机构情况、外出动向、类案雷达、应急呼救。参谋只能查询，不能修改台账。
- **数字不靠模型编**：所有数字、名称都来自工具查询结果；台账里没有的数据，要如实回答「台账中没有相关记录」。
- **证据编号逐一核对**：
  - 回答里引用的编号（EV-/MV-/IN-/CL-/SOS-），必须是本次查询结果中真实出现过的，否则由代码删除，并在执行过程和页脚注明删了几个。
  - 点击事件编号可以查看原始记录。
- **与老人端同一套架构**：大模型调用工具、规则兜底、执行过程可审计。模型一次都没查就回答时，先补查总览；未配置密钥时，按关键词路由调用同一组工具。
- **权限**：`POST /api/advisor` 仅监管端可用。
- **测试**：
  - 单元测试：`python3 scripts/test_advisor.py`。
  - 真实 DeepSeek 测试：`DeepSeek测试.bat` 新增「监管参谋」组，共 7 个问题。部分问题的标准答案由台账计算得出（例如未办结的高风险事件数、机构的投诉数），另有一个台账里没有数据的问题，检查 AI 会不会编造。

## 8.0：模型负责理解，代码兜底关键动作；一键 DeepSeek 测试

真实 DeepSeek 测试（Codex 报告）发现：模型有时不调用「生成工单 / 报备草稿」工具，电话号码在 110 和 12315 之间随机，命中防骗提醒后也不一定说出来。8.0 把可靠性要求高的部分从模型手里拿出来：

- **规则兜底（`agent.py` 的 `enforce_policy`）**：
  - 模型回答后，按意图检查关键动作：疑似诈骗必须有风险工单和提醒家属，消费投诉必须有投诉工单，出行必须有路线评估和报备草稿。
  - 缺了就由规则补上。执行过程里会显示黄色的「规则补全」步骤，不隐瞒是规则补的。
  - 这些动作仍需老人点确认才执行。
- **意图的安全下限**：
  - 出现要钱、验证码、稳赚、多收费等字眼时，不允许模型把问题当成普通咨询。
  - 出行只在模型没给出具体意图时，才按规则补判。
- **电话按场景固定**：疑似诈骗 110，消费投诉 12315，急症 120，出行与日常求助打机构值班电话。
- **命中防骗提醒**：由代码写入建议卡，界面单独显示黄色提示条，不依赖模型措辞；工单与提醒的关联也不再受工具调用顺序影响。
- **类案研判**：
  - 标题由归并结果确定，不随模型改写。
  - 模型写出证据里没有的核查结论（如「未登记」「无资质」），或直接定性（如「已构成诈骗」）时，整份研判退回模板，并在页面上注明。
- **用词**：「预警生效」提示不再写「未付款」，因为系统不核实付款结果。

**一键 DeepSeek 测试**：双击 `DeepSeek测试.bat`（需要 `deepseek.env.local`）。

- 跑 15 个用例 × 3 轮，外加 2 轮类案研判，大约 3～6 分钟，费用几毛钱。
- 每次调用都从 `seed.json` 复制一份全新数据，不读写数据库，前后互不影响。
- 用例分三组：
  - 演示用句：调提示词时用过的句子；
  - 自由说法：从没参与调优，用来看泛化能力；
  - 安全红线。

## 公开访问版本

GitHub Pages仅托管静态前端，使用浏览器独立数据，不具备跨设备共享和SQLite审计能力，也不会保存或公开DeepSeek API密钥。它用于小组在线浏览和备用展示；评审现场建议运行本地完整服务。

HTTPS页面不能直接“读取桌面API”：浏览器访问的 `127.0.0.1` 只指向每位访问者自己的电脑，无法指向你的桌面服务；把DeepSeek密钥放进前端也会造成泄露。若要让HTTPS版正式调用DeepSeek，应部署一个同样使用HTTPS的后端代理（如云服务器、Render、Railway、Vercel Function或Cloudflare Worker），由后端保存密钥，前端只请求 `/api/chat`，并配置域名白名单、登录鉴权、限流和日志脱敏。当前项目采用“HTTPS安全分流 + 本地完整DeepSeek服务”的交付架构，后续可无缝把代理地址切换到正式后端。

摄像头画面与原始音视频默认不上传。健康快筛属于非诊断性风险提示，不能替代医疗诊断。AI输出进入事件或台账前保留人工确认环节。

## 正式试点迁移

SQLite适合单机评审、离线运行和小规模试点。正式多机构部署时，建议保持现有表结构和审计模型，迁移至PostgreSQL，并补充统一身份认证、分级授权、传输加密、日志留存策略、备份恢复和属地接口联调。
