桂养安心·旅居智管 | 作品 v1

一、打开方式
1. 推荐双击“启动作品.bat”，访问 http://127.0.0.1:4173/。
2. 首次启动会自动创建 SQLite 业务数据库 runtime/guiyang_elders.db，无需安装数据库软件。
3. 本地完整服务支持三类角色共享数据、规范化业务表、操作审计和 DeepSeek 安全代理。
4. 直接双击 index.html 或访问 GitHub Pages 时使用浏览器独立数据，适合备用浏览，但不具备跨设备共享能力。
5. 测试账号：老人端 elder、机构端 center、监管端 admin，密码均为 123456。

二、建议评审顺序
1. 机构端：进入“动态台账”，新增一条外出报备，填写去向、返回时间、责任人和联系电话。
2. 监管端：进入“动向监管”，找到刚才的记录并完成责任链确认。
3. 监管总览：点击“操作审计”，展示机构报备和监管确认两条不可由业务页面修改的留痕。
4. 关闭并重新启动服务，刷新页面，说明记录和确认状态仍在 SQLite 中。
5. 老人端：使用“AI视频助手”输入问题，查看简短行动卡并生成求助事件，随后在机构或监管端继续处置。

三、数据库价值
- 核心数据分别落入老人档案、旅居、动向、服务、风险事件、处置节点、授权和审计表。
- 同一条动向贯穿机构报备、监管确认、返回核验和异常预警，避免只展示静态图表。
- 审计记录包含角色、操作者、动作、对象编号和时间，可回答“谁在何时处理了哪件事”。
- 数据库文件不提交 Git；脱敏种子数据可自动重建，便于比赛交付。
- 正式多机构试点可迁移 PostgreSQL，并接入统一身份认证、备份和主管部门接口。

四、AI与合规边界
- AI视频对话只发送老人主动表达的文字；摄像头画面和原始音视频默认不上传。
- AI负责风险筛查、办事指引和信息结构化，不作医学诊断，高风险结果必须人工确认。
- 当前生理指标属于赛事原型结果；正式使用须接入经验证的 rPPG 或医疗设备算法。
- DeepSeek不可用时自动切换本地安全规则，120、110、12315、12345等关键指引仍可使用。
- 属地责任单位和联系电话在正式部署前需由广西主管部门核验并接入真实渠道。

五、主要文件
- index.html / styles.css / app.js：三端业务界面与交互
- data.js / seed.json：脱敏初始业务数据
- server.py：静态站点、SQLite接口和DeepSeek安全代理
- database.py / database_schema.sql：数据库读写和规范化表结构
- DATABASE.md：数据库架构、评审呈现和正式迁移说明
- 启动作品.bat：一键启动本地完整服务
